Avant de commencer (Linux)

Installer J-ed sous Ubuntu, pas à pas, sans rien connaître à Linux, à Docker ni à PowerShell. Comptez une à deux heures la première fois, surtout du temps d'attente. Chaque commande dit ce que vous devez voir.

L'assistant J-ed (le fichier j-ed.sh) est un menu dans le Terminal : il installe J-ed, le met à jour, le vérifie, le sauvegarde et le restaure, comme la fenêtre de l'assistant sous Windows (mêmes fonctions, même ordre). Il vérifie lui-même chacun des points ci-dessous ; s'il manque quelque chose, il l'affiche avec un lien « Comment faire ? » vers la bonne partie de cette page.

1. Ce qu'il faut

  • Ubuntu 26.04 LTS Desktop, en 64 bits, à jour (c'est la version essayée ; une autre version récente d'Ubuntu devrait convenir, sans garantie).
  • 8 Go de mémoire conseillés (4 Go au minimum ; J-ed sera alors lent).
  • 20 Go de place libre sur le disque (voir plus bas), en plus d'Ubuntu.
  • Un processeur avec l'instruction AVX (presque tous les processeurs récents) : elle sert à la traduction hors ligne Argos et à l'IA locale. Dans une machine virtuelle, choisissez le type de processeur « host » (Proxmox : Hardware → Processors). Pour vérifier, dans le Terminal (étape 2) : grep -c avx /proc/cpuinfo Attendu : un nombre plus grand que 0.
  • Votre compte habituel, qui a le droit d'utiliser sudo (c'est le cas du compte créé à l'installation d'Ubuntu). sudo ne sert qu'aux étapes 3 à 7 ; l'assistant, lui, se lance sans sudo : il refuse de tourner en administrateur, sinon les fichiers de J-ed appartiendraient à « root » et vous ne pourriez plus les modifier.

2. Le Terminal

Toutes les commandes de cette page se tapent dans le Terminal.

  • L'ouvrir : Ctrl + Alt + T, ou « Afficher les applications » (en bas à gauche), puis tapez Terminal.
  • Coller une commande : Ctrl + Maj + V (Ctrl + V ne marche pas dans le Terminal), ou clic droit → Coller. Puis Entrée. Copiez chaque commande en entier, d'un seul bloc.
  • sudo devant une commande la lance en administrateur : Ubuntu demande votre mot de passe. Pendant la frappe, rien ne s'affiche (pas même des étoiles) : c'est normal, tapez-le puis Entrée.
  • Pas de message = tout va bien. Beaucoup de commandes n'affichent rien quand elles réussissent. Seuls « Erreur », « E: », « error » ou « Permission denied » signalent un problème : arrêtez-vous et lisez la partie En cas de problème.
  • ~ désigne votre dossier personnel (par exemple /home/votre-nom).

3. Derrière un proxy (réseau d'entreprise ou d'établissement)

Sans proxy, passez à l'étape 4. Derrière un proxy, rien ne joint Internet tant qu'il n'est pas réglé, et sous Linux chaque programme a son propre réglage : le bureau (navigateur), apt (les logiciels d'Ubuntu), curl (les téléchargements dans le Terminal), le service Docker, puis J-ed. Il vous faut l'adresse et le port du proxy (demandez-les à votre service informatique ; un fichier « PAC » ne suffit pas sous Linux). Dans cette page, remplacez partout NOM-DU-PROXY:PORT par ces valeurs, par exemple proxy.exemple.fr:8080 (adresse fictive).

Le bureau (navigateur)

Paramètres → Réseau → Proxy réseau → Manuel → l'adresse et le port pour HTTP et HTTPS ; dans « Ignorer les hôtes » : localhost, 127.0.0.1. L'assistant J-ed relira ce réglage et vous le proposera.

apt (les logiciels d'Ubuntu)

Gardez bien http:// devant et le / final, sur les deux lignes (même celle de « https » : c'est voulu). La première commande crée le fichier, la seconde y ajoute une ligne :

echo 'Acquire::http::Proxy "http://NOM-DU-PROXY:PORT/";' | sudo tee /etc/apt/apt.conf.d/95proxy

Attendu : la ligne est réaffichée.

echo 'Acquire::https::Proxy "http://NOM-DU-PROXY:PORT/";' | sudo tee -a /etc/apt/apt.conf.d/95proxy

Attendu : la seconde ligne est réaffichée.

cat /etc/apt/apt.conf.d/95proxy

Attendu : exactement les deux lignes, chacune avec "http://…:PORT/".

curl (téléchargements dans le Terminal)

curl ne lit pas le proxy du bureau : les commandes curl des étapes 5 et 7 portent l'option -x http://NOM-DU-PROXY:PORT. Sans proxy, retirez simplement cette option (les deux mots -x http://NOM-DU-PROXY:PORT).

4. Mettre Ubuntu à jour

sudo apt update

Attendu : des lignes « Atteint » ou « Réception de », puis « Lecture des listes de paquets… Fait », sans « Err » ; à la fin, « N paquets peuvent être mis à jour ».

sudo apt full-upgrade -y

Attendu : téléchargements, « Paramétrage de … », puis retour à l'invite (5 à 15 minutes). À un écran de question en mode texte : Entrée (réponse par défaut). Fermez la fenêtre « Mise à jour de logiciels » si elle s'ouvre.

sudo reboot

Attendu : l'ordinateur redémarre ; reconnectez-vous, puis rouvrez le Terminal.

5. Docker Engine

J-ed fonctionne dans Docker. Sous Ubuntu, on installe Docker Engine depuis le dépôt officiel de Docker (pas Docker Desktop, plus lourd, ni le paquet docker.io d'Ubuntu, souvent ancien). Il faut d'abord la clé de Docker (pour qu'apt vérifie que les logiciels viennent bien de Docker), puis déclarer son dépôt, puis installer.

sudo apt install -y ca-certificates curl

Attendu : « déjà la version la plus récente » ou installation faite.

sudo install -m 0755 -d /etc/apt/keyrings

Attendu : rien ne s'affiche.

sudo curl -fsSL -x http://NOM-DU-PROXY:PORT https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc

Attendu : rien ne s'affiche. (Sans proxy : sans -x http://NOM-DU-PROXY:PORT.)

sudo chmod a+r /etc/apt/keyrings/docker.asc

Attendu : rien ne s'affiche.

Déclaration du dépôt : une seule commande, à copier en entier d'un seul bloc :

printf 'Types: deb\nURIs: https://download.docker.com/linux/ubuntu\nSuites: %s\nComponents: stable\nArchitectures: %s\nSigned-By: /etc/apt/keyrings/docker.asc\n' "$(. /etc/os-release && echo "$VERSION_CODENAME")" "$(dpkg --print-architecture)" | sudo tee /etc/apt/sources.list.d/docker.sources

Attendu : six lignes, dont Suites: resolute (le nom de code d'Ubuntu 26.04) et Architectures: amd64.

sudo apt update

Attendu : une ligne de plus avec download.docker.com, sans « Err ».

sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Attendu : installation, puis retour à l'invite.

docker --version

Attendu : Docker version 29… (ou plus récent).

Le proxy du service Docker (seulement derrière un proxy)

Le service Docker (le programme qui télécharge les images) a son propre fichier de réglages :

printf '{\n "proxies": {\n "http-proxy": "http://NOM-DU-PROXY:PORT",\n "https-proxy": "http://NOM-DU-PROXY:PORT",\n "no-proxy": "localhost,127.0.0.1"\n }\n}\n' | sudo tee /etc/docker/daemon.json

Attendu : sept lignes, de { à }.

sudo systemctl restart docker

Attendu : rien ne s'affiche.

sudo docker info --format '{{.HTTPProxy}} {{.HTTPSProxy}} {{.NoProxy}}'

Attendu : deux fois l'adresse du proxy, puis localhost,127.0.0.1.

6. Le groupe docker

Pour utiliser Docker sans taper sudo à chaque fois, ajoutez votre compte au groupe docker ($USER est remplacé tout seul par votre nom) :

sudo usermod -aG docker $USER

Attendu : rien ne s'affiche.

Le groupe docker donne en pratique des droits d'administrateur sur l'ordinateur (Docker peut tout faire). C'est normal sur votre propre ordinateur ; n'y mettez pas n'importe quel compte.

L'appartenance à un groupe ne compte qu'à la session suivante : le plus simple est de redémarrer.

sudo reboot

Attendu : l'ordinateur redémarre ; reconnectez-vous et rouvrez le Terminal.

docker run --rm hello-world

Attendu : « Pull complete », puis « Hello from Docker! », sans sudo. Docker a téléchargé une petite image (à travers le proxy s'il y en a un), l'a lancée puis effacée.

7. PowerShell 7

L'assistant J-ed et ses scripts sont écrits en PowerShell, le même programme sous Windows et sous Linux (une seule logique à entretenir). Pour Ubuntu 26.04, on prend le paquet de PowerShell 7.6 (version à support long) sur la page des versions de PowerShell sur GitHub.

curl -fL -x http://NOM-DU-PROXY:PORT -o ~/powershell_7.6.10-1.deb_amd64.deb https://github.com/PowerShell/PowerShell/releases/download/v7.6.10/powershell_7.6.10-1.deb_amd64.deb

Attendu : une barre de progression jusqu'à 100 % (environ 54 Mo). (Sans proxy : sans -x http://NOM-DU-PROXY:PORT.)

sha256sum ~/powershell_7.6.10-1.deb_amd64.deb

Attendu : 81a5a944702b116ea74c88b01ba5f1f46b1cd7c42c36d85e1bae90de1230b4d1 suivi du nom du fichier. Cette « empreinte » prouve que le fichier est complet et intact ; si elle est différente, supprimez le fichier et téléchargez-le de nouveau.

cd ~ && sudo apt install -y ./powershell_7.6.10-1.deb_amd64.deb

Attendu : « Paramétrage de powershell ».

pwsh --version

Attendu : PowerShell 7.6.10. (Sous Linux, PowerShell se lance par la commande pwsh ; vous n'aurez pas à vous en servir : l'assistant le fait.)

8. Place sur le disque

Docker et J-ed occupent environ 10 Go ; prévoyez 20 Go libres (plus si vous installez l'IA locale).

df -h ~

Attendu : la colonne « Disp. » (disponible) indique au moins 20G.

9. Télécharger J-ed

  1. Dans Firefox, ouvrez la page des versions de J-ed : github.com/adupuisauteur/japon-explorateur/releases/latest.
  2. En bas, dans Assets, téléchargez les deux fichiers : japon-explorateur-X.Y.Z.zip et japon-explorateur-X.Y.Z.zip.sha256 (l'empreinte). Ils arrivent dans le dossier Téléchargements.
  3. Ouvrez l'application Fichiers, dossier Téléchargements : clic droit sur le .zip → Extraire. Un dossier japon-explorateur-X.Y.Z apparaît.

10. Ouvrir l'assistant

Dans le Terminal (remplacez X.Y.Z par le numéro de la version téléchargée, par exemple 2.0.3) :

bash ~/Téléchargements/japon-explorateur-X.Y.Z/j-ed.sh

Attendu : « J-ed — Assistant (Linux) », la liste de vos installations (aucune pour l'instant), la ligne « Prérequis : tout est prêt » en vert (sinon : choix 9 pour voir ce qui reste à régler, avec un lien « Comment faire ? » vers cette page), puis le menu.

  • Pour choisir, tapez le numéro, puis Entrée.
  • Une valeur entre crochets, par exemple [8001], est proposée : Entrée seule la garde. (O/n) : Entrée = oui ; (o/N) : Entrée = non.
  • Ne lancez jamais l'assistant avec sudo (il refuse, voir étape 1).
  • Si PowerShell manque, l'assistant le dit et renvoie à l'étape 7.

11. Installer J-ed

  1. Tapez 2 (Nouvelle installation).
  2. Proxy : s'il est réglé dans Ubuntu (étape 3), l'assistant le propose : Entrée pour l'utiliser. Il l'écrit dans le fichier .env de l'installation : J-ed s'en sert pendant la construction et pour interroger les sources en ligne.
  3. Archive : 2 (archive déjà téléchargée) et le chemin du .zip, par exemple ~/Téléchargements/japon-explorateur-X.Y.Z.zip (l'empreinte est trouvée à côté) ; ou 1 pour télécharger la dernière version depuis GitHub.
  4. Gardez le nom, le port, l'emplacement (~/J-ed/<nom>-<version>) et le dossier des sauvegardes (~/J-ed/sauvegardes-<nom>) proposés, ou changez-les ; répondez pour la traduction hors ligne Argos (conseillée, environ 2 Go de plus).
  5. « Vérifier d'abord que Docker joint Internet ? » : Entrée (oui). Si la réponse est non, revoyez le proxy du service Docker.
  6. Relisez le récapitulatif, puis Entrée (Installer).
  7. Attendez : la première installation prend 15 à 30 minutes (en fonction de la vitesse de téléchargement). Le Terminal montre chaque étape ; la construction peut rester longtemps sans nouvelle ligne : c'est normal. Elle se termine par « Installation réussie ».
  8. Fin guidée : 1 ouvre Firefox pour créer le compte administrateur (identifiant et mot de passe de 10 caractères au moins ; un seul clic sur le bouton) ; 2 charge le jeu d'essai (des notices fictives ; l'aide « Essayer J-ed » guide la visite) ; 3 crée les raccourcis du menu Applications ; 0 termine.
Aucune clé ni aucun mot de passe technique à inventer : l'assistant crée lui-même les clés secrètes de l'installation et les écrit dans le fichier .env de son dossier. Gardez une copie de ce fichier .env en lieu sûr (clé USB rangée, gestionnaire de mots de passe) : elle sera nécessaire pour passer J-ed sur un autre ordinateur ; elle ne figure pas dans les sauvegardes de J-ed. Ne l'envoyez à personne. (Le nom commence par un point : dans l'application Fichiers, Ctrl + H affiche ces fichiers « cachés ».)
Le dossier extrait à l'étape 9 ne sert qu'à lancer l'assistant la première fois : J-ed est installé dans son propre dossier (par exemple ~/J-ed/jed-X.Y.Z), qui contient aussi l'assistant. Ensuite, ouvrez l'assistant par le raccourci « Assistant J-ed » du menu Applications (touche Super, puis tapez « J-ed »), ou par la commande bash ~/J-ed/jed-X.Y.Z/j-ed.sh.

12. Mettre à jour, sauvegarder

  • 1. Mettre à jour une installation : même archive ou téléchargement depuis GitHub, puis l'assistant construit la nouvelle version pendant que l'ancienne fonctionne encore, et pose une question avant de l'arrêter : répondez o. Si la nouvelle version ne démarre pas, il revient tout seul à l'ancienne. Aucune donnée n'est effacée ; l'ancien dossier est gardé.
  • 10. Opérations de maintenance : créer une sauvegarde, ouvrir le dossier des sauvegardes, restaurer une sauvegarde (de préférence dans une nouvelle installation), mot de passe oublié, vérifier la migration, réinitialiser une installation d'essai.
  • Dossier des sauvegardes : J-ed y copie lui-même chaque sauvegarde, depuis son conteneur (utilisateur numéro 1000). Si votre compte n'est pas le premier de l'ordinateur, l'assistant peut afficher « J-ed ne pourra pas écrire dans … » avec la commande qui le permet, par exemple chmod o+rwx ~/J-ed/sauvegardes-jed ; l'assistant copie de toute façon la sauvegarde lui-même.

13. En cas de problème

Ce que vous voyezQue faire
apt : « Unsupported proxy configured » L'adresse du proxy est mal écrite : revoyez l'étape 3 (http:// devant, : avant le port, / à la fin), puis cat /etc/apt/apt.conf.d/95proxy.
apt ou curl : « Could not resolve host », « Connection timed out » Pas d'accès à Internet : vérifiez la connexion ; derrière un proxy, l'étape 3 (et l'option -x de curl).
« permission denied while trying to connect to the Docker daemon socket » Votre compte n'est pas encore dans le groupe docker : étape 6, puis redémarrez.
« Cannot connect to the Docker daemon » ; Docker « ne répond pas » Démarrez-le : sudo systemctl start docker, puis recommencez.
« Docker ne joint pas Internet » ; « context deadline exceeded » ; « failed to authorize: DeadlineExceeded » Derrière un proxy : revoyez le proxy du service Docker et acceptez le proxy proposé par l'assistant ; puis recommencez (l'assistant dit quel dossier raté peut être supprimé).
« Ne lancez pas … en administrateur (sudo ou root) » ; « Compte : lancé en administrateur » Relancez la commande sans sudo, depuis votre compte.
« PowerShell 7 n'est pas installé »Étape 7.
« Processeur : pas d'instruction AVX » J-ed fonctionne, mais sans Argos ni IA locale. Machine virtuelle : type de processeur « host » (étape 1).
« Le port … est déjà utilisé »Gardez le port libre que propose l'assistant.
Le disque est pleinLibérez de la place (étape 8).
Mot de passe de J-ed oubliéAssistant → 10 Opérations de maintenance → 4 Mot de passe oublié.
Autre choseAssistant → 11 Ça ne marche pas : un compte rendu (sans aucun mot de passe) est enregistré sur le Bureau ; envoyez-le à la personne qui vous aide.
